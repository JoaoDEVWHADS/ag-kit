# Multi-Agent Orchestration

Build entire SaaS platforms by coordinating specialist agents with the `/orchestrate` workflow.

## Overview

Most AI interactions are 1-on-1. The `orchestrator` agent changes this by acting as a **Project Manager**.
It breaks down a large request (e.g., "Build a SaaS MVP") into tasks and assigns them to the best specialist for the job.

The coordinator follows a portable lifecycle: **decompose, delegate, monitor, synthesize, and verify**. It uses native agent capabilities when the active host exposes them; otherwise it queues the required analysis envelopes and serializes dependent writes. Approval is adaptive: safe, bounded work can proceed automatically, while ambiguous, high-impact, or destructive actions require confirmation.

Before waiting, the coordinator dispatches exactly three independent **Eager Analysis Triad** envelopes and reviews each result individually before synthesis. Fewer than three domains use primary analysis, risk/edge cases, and verification planning; larger domain sets are grouped into three envelopes. Dependent writes stay sequential. Hosts without concurrency queue all three and declare the fallback without pretending simultaneous execution.

<Callout type="info">
  Codex, Claude Code, and Gemini are officially supported. Google Antigravity uses the Gemini adapter; OpenCode support is experimental. Concurrency depends on capabilities detected in the active host and is never assumed.
</Callout>

## The Process

<StepList>
  <Step number={1} title="Project Brief">
    Describe the high-level goal. The orchestrator will interview you to clarify requirements.

    ```bash
    /orchestrate Build a "Course Platform" MVP with:
    - User Authentication (NextAuth)
    - Stripe Payments
    - Video Hosting (Mux)
    - Dashboard for Instructors
    ```
  </Step>
  <Step number={2} title="Phase 1: Planning">
    The `project-planner` agent creates a detailed roadmap (`{task-slug}.md` in the project root).

    <div className="bg-zinc-50 dark:bg-zinc-900 p-3 rounded-lg text-xs font-mono border-l-2 border-blue-500 mt-2">
      ...<br/>
      ### 2.1 Database Schema<br/>
      - Users (id, email, role)<br/>
      - Courses (id, title, price)<br/>
      ...
    </div>
  </Step>
  <Step number={3} title="Phase 2: Execution">
    The Orchestrator delegates to native agents when available, runs independent tasks concurrently only when supported, and otherwise uses sequential specialist execution. It monitors progress, synthesizes results, and requires independent verification before completion.
  </Step>
</StepList>

## Pro Tips

<ProTips>
  <Tip title="Start Small">
    Don't try to build Facebook in one go. Orchestrate an MVP first, then use `/enhance` to iterate.
  </Tip>
  <Tip title="Define Auth">
    Always specify how users log in (e.g., "Use NextAuth with GitHub"). It's a key architectural decision.
  </Tip>
</ProTips>
